## One-Paragraph Summary

The project has a solid foundation — the Supabase schema, RLS policies, sign-in flow, deterministic matching library, skill dictionary, and four of the seven pages are built and mostly wired to real queries with mock fallbacks. However, the **single most important thing to know before building the next feature is that none of the four scheduled pipelines exist yet** (no cron routes, no `vercel.json`, no ingestion/indexing/sync/dispatch code), and **two pages are entirely missing** (Jobs and Skills). The existing AI routes also contain a subtle but real deviation: `POST /api/gap-report` does not enforce Supabase session auth at the top of the handler before writing to profile-scoped tables, and `POST /api/tutorial-search` uses a substring fallback instead of the required AI `embed` + pgvector cosine similarity search. These are the kind of "looks done, runs, but doesn't match spec" issues that will compound if not fixed before the pipelines and pages that depend on them are built.

## ⚠️ Deviations Found (Consolidated)

These are the items where the implementation exists but contradicts a specific AGENTS.md rule. They are listed again here so they cannot be lost in the longer report above.

1. **`POST /api/gap-report` does not validate Supabase session at the top of the handler (Section 3).** The route writes to `user_skill_profiles` and `gap_report_events` (lines 119–127) without first calling `supabase.auth.getUser()` and returning 401. The auth check happens later in a try/catch "best-effort" block. AGENTS.md Section 3 is explicit: "any API route touching `user_skill_profiles` ... must call `supabase.auth.getUser()` server-side and reject with 401 if there is no valid session."

2. **`POST /api/tutorial-search` uses substring fallback instead of AI `embed` + pgvector cosine similarity (Section 15 Feature 3).** The route queries `tutorial_chapters` with `.in("video_id", videoIds)` and filters by `c.label.toLowerCase().includes(skill)` (lines 55–65). Comments on lines 41–54 explicitly acknowledge this is a demo fallback. AGENTS.md Section 15 requires: Stage 1 must call `embed` on the skill name, then run pgvector cosine similarity against `tutorial_chapters.label_embedding` restricted to video_ids from `tutorial_chunks`, with a distance threshold. Stage 2 must fall back to `tutorial_chunks` only for videos with no accepted chapter match.

3. **`trends-summary` and `gap-report` AI model passed via `as unknown as string` cast (Section 9 / Section 15).** Both routes do `model: model as unknown as string` (lines 84 and 151–152). In Vercel AI SDK v7, the Gateway string format (`'provider/model-name'`) is valid, but the cast suggests the developer was working around a type mismatch rather than configuring the Gateway explicitly. The `package.json` has no `@ai-sdk/groq` or `@ai-sdk/anthropic` packages — only `ai` — which is consistent with Gateway-only usage, but the cast obscures intent.

4. **RLS policies use `for all to authenticated` instead of `for all` (Section 11).** `002_rls_policies.sql` adds `to authenticated` to every policy (lines 13, 20, 26, etc.). AGENTS.md Section 11 specifies `for all using (auth.uid() = ...)` without the `to authenticated` clause. Functionally equivalent, but not a literal match.

5. **`trends-summary/route.ts` has its own inline skill allowlist instead of importing from `lib/skills-dictionary.ts` (Section 14).** Lines 31–59 define a hardcoded `allowed` Set with 27 skills. The route should validate against `ALL_SKILLS` or `isKnownSkill` from the dictionary.

6. **`SkillsToConsiderCard` uses mock tutorials directly instead of calling `/api/tutorial-search` (Section 15 Feature 3 / Section 6).** `components/gap-report/SkillsToConsiderCard.tsx` line 15: `const tutorials = mockTutorialsBySkill[active.toLowerCase()]`. The tutorial-search API route exists but is never called from any page component.

7. **No Next.js middleware exists for auth redirects (Section 3).** `app/(app)/layout.tsx` has a server-side guard, but there is no `middleware.ts` at the project root. AGENTS.md mentions "Middleware or per-page guard" — the per-page guard exists, but middleware would provide defense-in-depth at the edge before the server component renders.

## Suggested Close-Out Order

The following is a dependency-ordered list of what the gap-closing prompt should tackle first. Items at the top block items below them.

1. **Fix `POST /api/gap-report` auth validation** — Add `supabase.auth.getUser()` + 401 rejection at the top of the handler, before any Supabase writes. This is a security deviation that should be fixed before any other gap-report work.

2. **Fix `POST /api/tutorial-search` to use AI `embed` + pgvector cosine similarity** — Replace the substring fallback with the two-stage embedding search AGENTS.md Section 15 requires. This unblocks real tutorial matching for the Gap Report page.

3. **Create the four cron routes + `vercel.json`** — Daily ingestion (`/api/cron/ingestion`), weekly tutorial indexing (`/api/cron/tutorial-index`), weekly GitHub sync (`/api/cron/github-sync`), and alert dispatch (`/api/cron/alert-dispatch`). Each must check `CRON_SECRET`. These are the backbone of the product; pages like Dashboard and Jobs depend on ingestion having run.

4. **Build the Jobs page (`/jobs`)** — Missing entirely. Depends on cron ingestion having run and on `lib/matching.ts`'s `stackMatchPct` being wired in.

5. **Build the Skills page (`/skills`)** — Missing entirely. Depends on the skill dictionary validation and the `POST /api/gap-report` auth fix.

6. **Build `GET /api/jobs/{id}/summary`** — Feature 4 (job posting restructuring) is the only AI feature whose route does not exist.

7. **Fix `trends-summary/route.ts` to use the skill dictionary** — Replace the inline `allowed` Set with an import from `lib/skills-dictionary.ts`.

8. **Wire `SkillsToConsiderCard` to call `/api/tutorial-search`** instead of using mock data.

9. **Add Next.js middleware** for auth redirects — Provides defense-in-depth before the layout guard.

10. **Fix RLS policy text** (`for all to authenticated` → `for all`) to match AGENTS.md Section 11 literally.

11. **Install missing dependencies** (`resend`, `octokit`, `youtube-transcript`) and verify `AI_MODEL` provider supports embeddings for Feature 3.
