# Implementation Prompt — Profile Skills → Gap Report Live Sync & Tutorial Teaching Quality (4–7 videos)

## Goal
Fix two linked product gaps:

1. **Profile → Gap Report reactivity.** When the signed-in user adds/removes Core Skill Stack entries on `/profile` or when the weekly GitHub sync (`/api/cron/github-sync`) folds public-repo languages/topics into `user_skills` (source `github_sync`), the Gap Report page (`/gap-report`) still shows stale gaps/tutorials until a hard reload. Gaps must derive deterministically from the current `user_skills` baseline every visit and after every in-app re-analyse, so a newly-added high-demand skill immediately leaves "Skills to consider" and appears in "Strengths" (and vice-versa on removal).

2. **Tutorial quality + quantity.** The Gap Report's "Skills to consider" panel currently returns 1 explainer video per gap skill (e.g. mock `kubernetes: "Kubernetes in 100 Seconds"` 2:18). It must return **4–7 distinct teaching videos per gap skill**, each a real learning entry point (>3 min, ideally >10 min, viewCount>10k), chapter-anchored when chapters exist, transcript-chunk fallback otherwise — so the user has genuine choice and is not shown a single short explainer. This requires both a live-path fix (`/api/tutorial-search`) and mock/indexer/data-scale fixes.

Both are credibility fixes: deterministic percentages (AGENTS §13) and grounded tutorial rows (AGENTS §15 Feature 3) must remain verifiable against Supabase; no AI-invented numbers or fabricated chapters.

## Decisions & Assumptions
- **Gap Report is derived, not stored.** `app/(app)/gap-report/page.tsx` must recompute gaps from live `user_skills` on every request (`force-dynamic`). No caching layer is added. The fix is invalidation + fetch completeness, not a new table.
- **Profile → gap-report invalidation path:** adding/removing a skill via `/api/profile/skills` already calls `router.refresh()` which revalidates the *current* route (profile). Gap-report on another route does not revalidate until navigation. Add server-side `revalidatePath("/gap-report")` inside `POST`/`DELETE /api/profile/skills` (and optionally `PUT /api/profile` when skills-relevant fields change) so the next navigation to `/gap-report` is fresh, and add a client affordance on gap-report itself: a **"Sync from profile" / "Refresh from profile"** control inside `GapReportClient`/`YourSkillsPanel` that refetches `GET /api/profile/skills` and re-runs `POST /api/gap-report` with the fresh baseline. This satisfies Evans's wording: "when the user updates the skills and syncs their github profile the suggestions in the gap-report should update" — without coupling the two pages via polling or websockets. Polling is rejected (noisy). Real-time Supabase Realtime subscription is deferred (would require RLS + channel setup, out of scope for this slice).
- **GitHub sync trigger:** cron is weekly and profile page shows "Next sync: Sunday 04:00 UTC" (display-only). We do not build an immediate per-user GitHub sync button that calls `api.github.com` from the browser — that would violate §2 (browser never calls GitHub). If Evans wants an on-demand server-side sync button, it would POST to a new `/api/profile/github-sync` that reuses the cron's service-role logic but rate-limited per user; out of scope for this slice unless approved. For now, ensure the *next* gap-report load after a sync run reflects the new `github_sync` skills because `user_skills` is already read inclusively.
- **Tutorial quantity: 4–7 distinct videos.** Raise the API cap from `slice(0,5)` to `slice(0,7)` and ensure inputs can supply that many: fix the `limit(1)` bug, raise `match_count` to 14 (2× target for headroom after dedupe/threshold), raise `MAX_VIDEOS_PER_SKILL` from 5 to 7 (matching the requested upper bound) while staying well under quota (`40 skills × 7 videos × (search + videos.list) ≈ 80 search units + 280 video units ≈ 360 units/day avg`, still under 10k). No quota breach.
- **Teaching vs explainer quality.** Filter at two layers:
  - *Indexer layer:* raise `MIN_DURATION_SECONDS` from 180 (3 min) to 600 (10 min) or apply a tier — Shorts remain excluded by 180, but explainers like "in 100 Seconds" (2:18) are currently <180 and would already be filtered — yet mock allows it, and a 4-min explainer would still pass. Prefer `MIN_DURATION_SECONDS = 600` for teaching (tutorial/course/crash course are rarely <10 min). If Evans prefers more lenient, keep 180 but add a title filter excluding `/\bin\s+\d+\s*(seconds?|minutes?|mins?)\b/i` and preferring titles containing `tutorial|course|crash course|full|beginners|complete`. Choose 600 as default, document as assumption to confirm.
  - *Search layer:* change YouTube `q` from `"{skill} tutorial"` to `"{skill} complete tutorial course"` to bias toward teaching content (still `order=relevance`, `publishedAfter=2y`). Alternative considered: multiple queries per skill (tutorial + course) would cost 2× quota — rejected for now.
  - *Retrieval layer:* deduplicate by `video_id` *before* slicing (current code does per-result dedupe partially via chapterVideoIds set, but chunk hits can still contain multiple rows per same video with different `start_seconds`). Ensure final `results` are grouped to **distinct `video_id`**, taking the best (smallest distance) hit per video, then sort and slice 4–7.
- **Chapter-first invariant preserved.** Stage 1 `match_tutorial_chapters` restricted to `videoIds` for this skill still applies (§15 Feature 3). Stage 2 `match_tutorial_chunks` fallback only for videos without an accepted chapter. Badge rule preserved: `chapter_label` only on Stage 1 results, never synthesized.
- **Mock path must also return 4–7.** Expand `lib/mock/gap-report-tutorials.ts` so local dev/has-no-index path is not the reason QA sees 1 video. Remove the `PH-2FNrRwjs "Kubernetes in 100 Seconds"` explainer mock entirely; replace with real teaching titles (freeCodeCamp/Traversy/TechWorld with Jay/etc., durations `1:00:00`–`4:00:00`, some with `chapter_label` like `CH 2: CONTROL PLANE`). Each skill used in gaps (`kubernetes`, `rust`, `graphql`, plus `go`, `python`, `aws`) gets 4–7 entries.
- **Threshold & embedding scope:** keep `DISTANCE_THRESHOLD = 0.5`, `embedding = skill` canonical name (per §15 start-simple). If later too sparse at 0.5 with stricter duration, tune threshold or enrich embedding with `"{skill} complete tutorial for beginners"` — flagged as follow-up, not in this slice.
- **No service-role leakage, no browser YouTube calls.** Thumbnail/embed URLs remain the only public YouTube endpoints allowed client-side (§2 exception). `googleapis.com/youtube` stays only in `app/api/cron/tutorial-index`. `api.github.com` stays only in `app/api/cron/github-sync`. Profile-scoped routes validate `supabase.auth.getUser()` server-side before any write/read of `user_skills`/`profiles`.
- **Files deliberately NOT touched:** `lib/skills-dictionary.ts` (no expansion needed — 31 skills sufficient), `supabase/migrations` (no schema change — `tutorial_chapters`/`tutorial_chunks` already support distinct-video queries), `lib/matching.ts` (deterministic formulas unchanged), `vercel.json` (cron schedules unchanged).
